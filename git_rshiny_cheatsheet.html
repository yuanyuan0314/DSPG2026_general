Git + R Shiny

A step-by-step guide to setting up your project, building a Shiny dashboard, and collaborating with GitHub.

01

Pull the repo into RStudio

RStudio

Instead of using the terminal, you can clone a GitHub repo directly inside RStudio by creating a new project.

1. In RStudio: File → New Project → Version Control → Git
2. Paste your GitHub repo URL (e.g. https://github.com/username/repo.git)
3. Choose a local folder → click Create Project

This clones the repo and opens it as an RStudio project in one step. The Git tab will appear in the top-right panel.

02

Create your Shiny app and folders

R

Create the Shiny app file

In RStudio: File → New File → Shiny Web App
Set the folder to ShinyApp/ inside your project

This creates a ShinyApp/app.R file with a basic template already inside.

Create www/ and data/ folders manually

These folders won't be created automatically — you need to make them yourself inside the ShinyApp/ folder.

your-repo/ ├── ShinyApp/ │ ├── app.R │ ├── www/ # images go here │ │ └── plot1.png │ └── data/ # data files go here │ └── mydata.csv └── .gitignore

To ignore data files from GitHub, add ShinyApp/data/ to your .gitignore.

03

Build your app — v1 to v5

R

v1 — skeleton

library(shiny)

ui <- navbarPage("My App")

server <- function(input, output) {}

shinyApp(ui, server)

v2 — add a page with a title

ui <- navbarPage("My App",
  tabPanel("Overview",
    h3("Daylighting", style = "text-align:center; color:#861F41;")
  )
)

All four pages follow the same pattern: tabPanel("Page Name", ...content...) separated by commas inside navbarPage().

v3 — three-column text layout

fluidRow(           # columns inside always add up to 12
  column(4, h3("Col 1"), p("text...")),
  column(4, h3("Col 2"), p("text...")),
  column(4, h3("Col 3"), p("text..."))
)

4+4+4 = 12 (three equal columns). Use 6+6 for two, 3+9 for unequal.

v4 — multiple paragraphs

column(4,
  p("First paragraph..."),
  p("Second paragraph..."),  # p() adds paragraph spacing
  br(),                       # br() is a smaller blank line
  p("Third paragraph...")
)

v5 — insert an image

img(src = "plot1.png", width = "100%")

Put the image inside ShinyApp/www/. Shiny finds it automatically — just write the filename in src, no path needed.

04

Publish your app

R
step 1 Create a free account at shinyapps.io
step 2 Install & connect
install.packages("rsconnect")

# Copy this from your shinyapps.io dashboard
rsconnect::setAccountInfo(
  name   = "your-username",
  token  = "xxxxxxxx",
  secret = "xxxxxxxx"
)
step 3 Deploy
rsconnect::deployApp()

Or click the Publish button in RStudio (top right of app.R). Your app goes live at username.shinyapps.io/projectname

05

Push your work to a branch

Git

Full branch workflow

# 1. Make sure main is up to date
git pull origin main

# 2. Create and switch to your branch
git checkout -b my-branch-name

# 3. After editing — stage and commit
git add .
git commit -m "describe what you changed"
# shortcut (only if no new files):
git commit -am "describe what you changed"

# 4. Push branch to GitHub
git push origin my-branch-name
5. On GitHub: click "Compare & pull request"
6. Click "Create pull request" → "Merge pull request" → "Confirm merge" 
# 7. Back in terminal — update your local main
git checkout main
git pull origin main

# 8. Delete branch (optional)
git branch -d my-branch-name
git push origin --delete my-branch-name
06

Handling conflicts

Git

A conflict only happens when two people edited the exact same line. Git marks the conflict directly in your file:

<<<<<<< your-branch
plotOutput("my_plot")      # your version
=======
plotOutput("team_plot")    # teammate's version
>>>>>>> main

To fix it — open the file, delete the markers, keep the correct version, then:

# Pull main first (this is what triggers the conflict markers)
git pull origin main

# After editing the file manually
git add .
git commit -m "resolve conflict"
git push origin my-branch-name
Your existing Pull Request updates automatically — just go back and merge.

Best prevention: each person owns different files. You do overview, teammate does finding — conflicts almost never happen.
